             samples/Trustsoft.NotifyIcon.Sample/bin/Release/net8.0-windows/Trustsoft.NotifyIcon.Sample.exe 16 \
             --balloon-after 6 --menu-after 11
Result:  probe exit 0. The startup line names the effective triggers and shows the sample args it composed
         ('sample args: --show-balloon-after 6 --open-menu-after 11'); the balloon request is followed by the
         shell's own acceptance callback event=0x0402 (NIN_BALLOONSHOW) for iconId=1, the identity the probe
         resolved independently; the menu opens at rect=1542,1045 296x83, i.e. directly above the icon at
         (1542,1128)-(1590,1200) and 83 px tall, with dpi=144 applied once. Both are post-registration
         behaviours driven with no human at the keyboard, which is what T04 composes.

Part B - the positive control: the after-exit oracle can say 'still present'
---------------------------------------------------------------------------
Command: dotnet run --project scripts/probe-live -c Release --no-build -- \
             samples/Trustsoft.NotifyIcon.Sample/bin/Release/net8.0-windows/Trustsoft.NotifyIcon.Sample.exe 6 \
             --keep-sample-alive
Result:  probe exit 0. The same Shell_NotifyIconGetRect call, for the same identity, reports 'still present'
         while the process lives and 'gone' once it is dead (docs/uat-logs/S05/t03-plan-verify.txt), so the
         teardown verdict is a change in the shell's answer and not a constant. The sample left running by
         --keep-sample-alive was terminated afterwards with: taskkill //f //im Trustsoft.NotifyIcon.Sample.exe
