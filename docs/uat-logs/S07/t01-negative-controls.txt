## verdict
  Three controls, three named failures, each naming the offending project and property.
  The byte-for-byte restore above is what proves this driver left nothing behind.
  The green re-run of the same guards, and the pack inspection, are deliberately NOT part of
  this driver: they are executed as separate fresh commands. The build failure this driver is
  careful not to leave behind was measured to come from the shell's environment, not from the
  repository: a shell that arrives without the Windows profile variables (APPDATA,
  LOCALAPPDATA, ProgramData) makes a build fail during NuGet's restore graph evaluation - exit 1,
  'Value cannot be null. (Parameter 'path1')' from NuGet.targets GetRestoreSettingsTask - while
  the same content and the same user build with 0 errors once those variables are present. This
  driver fills them in when they are absent, and the environment it ran in is printed above.
  Nothing about the repository is left inconsistent, and the cmp check above is the guarantee of
  that.
